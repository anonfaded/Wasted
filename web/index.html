Setup guide
  1. Create a free Supabase project at supabase.com/dashboard.
  2. In the Wasted app, open Remote Management → Open setup wizard. Paste the project URL and publishable key from the Supabase Connect dialog or Settings → API Keys. Never use the secret/service-role key.
  3. In Supabase, open the SQL Editor and run the setup SQL copied from the wizard (one paste). Then in Authentication → Providers: enable “Allow anonymous sign-ins”. Under Providers → Email, keep the Email provider ON (it enables email/password sign-in), but turn Confirm email OFF. Then open Authentication → Hooks → Before User Created: turn the hook ON, set Hook type: Postgres, Postgres schema: public, select Postgres function: hook_single_owner_signup, and click Save.
  4. In the wizard, save the deployable ZIP. In Netlify, choose Add new project → Deploy manually and upload the ZIP. For later updates, use that same project → Deploys and upload the new ZIP.
  5. Open your new dashboard URL and create the owner account before sharing the URL; this project allows one owner.
  6. In the app, paste the hosted URL into Remote Management, Save, and Enable. Create an enrollment token on the Devices tab and claim it in the app.
  7. Send Reset Timer here and confirm the device card updates.

Owner signup: signup is direct and no email is sent. The first account becomes the owner. This dashboard is deliberately single-owner: the Before User Created hook blocks every later email/password signup, even if someone finds the dashboard URL, while anonymous device identities remain allowed. Keep the URL private until the owner account exists.

Changing your account: use the Account section to see the signed-in email and change the display name. Password reset or account recovery is handled by the Supabase project owner from the Supabase dashboard, because this setup deliberately does not depend on email delivery.

Account name: saved to your Supabase account. Sign in on another browser and the same name appears under Account. You can change it there later.

The dashboard package contains only your project URL and publishable key — these are public by design, so sharing it does not leak secrets. Anyone who can open the hosted dashboard can attempt to create an account, though your data stays protected by the database rules. Keep the URL private if you do not want that. Never share your Supabase password or a secret key.

Updating: upload the new ZIP to the same Netlify project through Deploys. Do not replace only index.html, and do not create a new site; that changes the URL and requires updating Remote Management.

    Global defaults

    Global trigger settings

    These values apply to every device that has not overridden the field. Lock trigger arms the lock workflow; Lock delay sets how long it waits after screen-off/lock; USB trigger is separate. All three are saved together in one global version. A device override wins until you clear it in that device's Settings. Wipe data remains phone-local and is never changed by this page.

    Lock trigger

    Global default for the lock workflow. Devices with a Lock trigger override use their own value. When the countdown finishes, Wasted locks the phone; if Wipe data is on, the reset starts (Debug Mode blocks the wipe).

    How long the phone waits after it locks or its screen turns off before firing the Lock trigger. It runs only when the Lock trigger is ON. Enter whole minutes: 10080 = 7 days, 1440 = 1 day, 90 = 1 hour 30 minutes, 60 = 1 hour.

    USB trigger enabled

    When enabled, connecting USB data while the device is locked can fire the USB trigger. This is independent of the Lock trigger and delay.

    Custom limits

    Command & enrollment limits

    These defaults are enforced by the backend when a command or enrollment token is created. Shorten them to avoid stale actions; lengthen them to give offline devices more time. Changing a limit affects new commands only.

    A new token must be claimed within this many minutes. Existing tokens keep the lifetime they were created with. Default 10 minutes.

    If a selected phone is offline, keep the Lock Devices command ready for this many minutes. After that it expires and is not applied. Default 5 minutes.

    If a selected phone is offline, keep the factory-reset request ready for this many minutes. After that it expires and is not applied. A shorter wait is safer. Default 10 minutes.

    If a selected phone is offline, keep the Reset Timer request ready for this many minutes. After that it expires and is not applied. Default 24 hours.

    If the phone is offline, keep the request to turn Debug Mode ON ready for this many minutes. After that it expires. Default 24 hours.

    If the phone is offline, keep the request to turn Debug Mode OFF ready for this many minutes. OFF allows destructive commands, so keep this short. Default 10 minutes.

    How this works

    This page was generated by the Wasted app and hosted by you. It connects directly from your browser to your own Supabase project: sign-in, data, and commands all live there. There is no dashboard server; the browser only queues a command, and the enrolled app performs the actual reset after its own Debug Mode checks.

    Your email/password is only for this dashboard. Devices do not receive it. Instead, the app creates a private, unnamed identity for each device, and the one-time enrollment token links that identity to your account. That is why device enrollment asks for a token, not an email.

    Anonymous sign-ins are how those device identities are created. They can be left off if you do not want Remote Management; your owner account still works, but devices cannot enroll or sync. Rate limits and automatic cleanup of unused identities limit abuse.

    1. In Supabase, run the setup SQL, enable anonymous sign-ins, keep the Email provider on, turn Confirm email off, and enable the Before User Created single-owner hook.
    2. Create the first account on this page; it becomes the owner immediately.
    3. In the app, paste this page's URL under Remote Management, Save, and Enable.
    4. Create an enrollment token on the Devices tab, then claim it in the app.
    5. The device appears after its first sync.

    The header menu shows the configured Project URL, publishable key, and hosted Dashboard URL with copy buttons. The connection values are baked into this page and the Dashboard URL comes from the address you are using, so reading or copying them makes no Supabase request. The publishable key is public by design; never paste a secret or service-role key here.

    What each device field means
    Connection
    Active means the device contacted the server within the last 150 seconds; Inactive means it has not. The exact last-contact time is shown below. Commands stay queued until it reconnects, subject to the configurable limits in Controls (default: Reset Timer 24 hours; Force Reset and Debug Mode OFF 10 minutes; Debug Mode ON 24 hours).
    Live countdown
    The live remaining countdown before the Lock trigger fires, shown in days, hours, minutes, and seconds. It starts after the phone locks or its screen turns off, stops when the phone is unlocked, and stays inactive when the Lock trigger is OFF. The value is extrapolated every second from the last real device report, so it is labelled estimated while running.
    Lock trigger
    The switch that arms the lock workflow. The saved value is the device override when one exists, otherwise the global default. Green ON means armed; red OFF means disarmed. When the countdown finishes, Wasted locks the phone and, if Wipe data is on, starts the reset (Debug Mode still blocks the wipe).
    Lock delay setting
    The wait after screen-off/lock before the Lock trigger fires. It runs only while the Lock trigger is ON. “Device reports” is the phone's delay, converted from whole minutes and shown with only non-zero units. “Saved setting” is the device override, otherwise the global default. Wipe data is a phone-local setting and is not changed by the dashboard.
    USB trigger
    When ON, a USB data connection while the phone is locked can fire the trigger. Green ON means armed; red OFF means disabled. “Device reports” is the phone's value; “Saved setting” is the device override, otherwise the global default. Changing the switch on the phone affects only that phone and does not rewrite either target; the card shows the mismatch until they agree.
    Battery
    Battery percentage and charging state reported at the last status sync, with a filled battery icon. Green is healthy, amber is 21–50%, red is 20% or less, and a dashed grey/unknown icon means the phone did not report a value; unknown is not the same as 0%. The value updates about once a minute, not continuously.
    Settings status
    Current is green and means the device has applied the latest global and per-device override revisions. Pending is amber and means the next sync is still outstanding. The applied time is recorded by the server when the device reports a new revision.
    Settings version
    Global and device versions are independent. Saving global settings increments the global version; saving a device override increments only that device's version. Devices apply the saved value from both. Neither version needs to match by hand.
    Device settings
    Each card's Settings button overrides Lock trigger, Lock delay, or USB trigger for that device only. Check Inherit global to remove an override. Global saves never clear overrides; no other device is affected.
    Device notes
    Private owner-only notes attached to one device. Use the Notes section on a device card to add or edit up to 4000 characters. Notes are stored in Supabase and are never shown in the Wasted app or sent to the phone.
    Command targets
    Choose All enrolled devices or select devices in the Command targets list. The command confirmation lists the exact count and names. Selected targets must be enrolled and owned; a revoked or empty selection is rejected before any command is queued. A newer copy of the same action replaces older queued copies for that device; other actions remain queued independently.
    Command & enrollment limits
    Controls how long commands and enrollment tokens stay valid. Defaults are the normal values; changes apply to new commands and tokens only. Existing queued work keeps the expiry it was created with.
    Debug Mode
    Green ON blocks destructive remote commands (Force Reset); red OFF allows them. Reset Timer and settings sync keep working. Enable/Disable sends a command to that device only.
    Reset support
    Whether this device can run a reset at all with its current Device Admin/Device Owner protections. Android 14+ installs that are not Device Owner may use a best-effort wipe rather than a full factory reset.
    Last command
    The newest remote command for this device and its state (queued, executing, applied, blocked, failed, …).

    How to test safely
    1. In the app, open Remote Management and confirm it is enabled and enrolled.
    2. Turn Lock trigger ON in the dashboard if you are testing the lock delay. Turn Debug Mode ON before testing any reset path.
    3. Change Lock delay or USB trigger here, press Save trigger settings, and wait for the device card to report the new value. The app should update without reopening it.
    4. Press Reset Timer and confirm the Lock countdown restarts only while the phone is locked and the Lock trigger is ON.
    5. Test Force Reset only with Debug Mode ON. It must be blocked and reported; do not test a real wipe on a device you need.

    A local change in the app is reported back as the device value, but it does not rewrite the global or device target. Use the device's Settings button for one device; use Global settings for every device that inherits the field. Select one or more devices in Command targets before sending a command, or choose All enrolled devices.

    When the countdown completes, Wasted fires the Lock trigger: it locks the phone. If Wipe data is ON, it then starts the reset; Debug Mode blocks that wipe. After the delay has elapsed the countdown stops until the phone is locked again.

    Safety notes

    Force Reset is destructive and cannot be undone. It is blocked when Debug Mode is ON and requires typing RESET in the confirmation dialog. It does not consult the phone's local Wipe data switch; that switch only controls trigger behavior. Force Reset is an explicit reset command.

    Lock Devices only locks the screen on the selected targets; it never wipes or changes settings. It asks twice, and an offline device ignores it after the configured Lock Devices expiry (default 5 minutes).

    Revoking a device stops remote commands but does not wipe it. Reset enrollment in the app is separate and local; it does not remove the dashboard device record. The record is retained for audit, and revoking it stops remote access.
