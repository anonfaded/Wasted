# Hosting the dashboard

The dashboard is **generated by the app** as one self-contained HTML file. It contains only the
project URL and publishable key and talks directly to Supabase over HTTPS/WSS. There is no dashboard
server, database credential, or CDN dependency.

## Steps (Netlify Drop — simplest)

1. In the app: **Remote Management → Open setup wizard** → enter project URL + publishable key.
2. Tap **Generate dashboard file** and save `wasted-dashboard.html` via the Android file picker.
3. Open <https://app.netlify.com/drop> and drag the file in.
4. Netlify gives you an HTTPS URL (`https://…netlify.app`). Claim the site to keep it online;
   unclaimed deployments are password-protected until claimed.
5. Open the URL, create your account, then enter it in the app and enable Remote Management.

## Alternatives

- **Cloudflare Pages** — Create project → direct upload → drop the file.
- **GitHub Pages** — publish from a `docs/` folder or an Actions workflow.
- **Vercel** — `vercel deploy --prod` from a folder containing only `index.html`.
- Any HTTPS static host (S3 + CloudFront, nginx, Caddy, …).

No redirect URLs or CORS setup is needed (password sign-in only). HTTPS is required.

## Updating the dashboard

Regenerate the file in the app and drag the new file to the same host. Keep the previous file if you
want a rollback path. If the publishable key rotates, regenerate the file and update the app's saved
key.

## Backups and restore

Hosting has no data to back up: the dashboard is stateless and the database lives in Supabase. Back
up Supabase before schema updates; see [updates.md](./updates.md).

## CSP and custom domains

The page ships a restrictive CSP meta policy allowing only `*.supabase.co` connections plus inline
scripts/styles, and `no-referrer`. If you use a custom/self-hosted Supabase domain, adjust the CSP
and rebuild. For strict deployments, serve the config externally and use response-header CSP hashes
plus `frame-ancestors 'none'` (meta policies cannot set framing rules).

## Why not environment variables?

This is a static page: any value the browser needs is delivered to the browser. Netlify-style env
vars only help build steps/functions; they do not hide values from visitors. The publishable key is
public by design, and the secret key must never be in the page.
